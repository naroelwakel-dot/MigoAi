# تحقق SheerID على الموقع — مرآة أتمتة البوت (Google Student)

نفس مسار التحقق الآلي اللي شغّال في بوت التيليجرام، على موقع
migoai.shop وبنفس العقد مع خدمة التحقق والتسويات والضمانات:

| خطوة البوت | مرآتها على الموقع |
|---|---|
| منتج مُعلَّم `custom.automation="sheerid"` بسعر ثابت 280 ج | بطاقة `google_student` في `ai-tools.js` بسعر ثابت 280 ج + صف كتالوج `Google Student (سنة كاملة)` |
| الطلب بيفتح عملية `awaiting_link` + رسالة إرشاد | العملية بتتفتح من أول مشاهدة لحالة الطلب المدفوع أو من المسح، والإرشاد بيظهر في لوحة الفاتورة |
| العميل يبعت الرابط في المحادثة | العميل يلصق الرابط في لوحة التحقق بصفحة فاتورته (إثبات ملكية: رقم الطلب + حساب المُرسل — نفس `get_invoice`) |
| تحقق صارم من الرابط + بوابة رصيد + إرسال + استطلاع +20/+40 ث | نفس الشيء حرفيًا في `service.ts` |
| نجاح: الطلب fulfilled + رسالة التفعيل بتتبع تسليم | نجاح: رابط التفعيل محفوظ وبيظهر في الفاتورة + إيميل Brevo من orders@، و`delivered_at` بيتمنع بعده أي إعادة (التسليم = الإيميل المتتبَّع؛ مشاهدة الفاتورة بتعرض الرابط لكن ما بتعلّمش التسليم — إصلاح لجنة 2026-11-19) |
| فشل: إلغاء + استرداد محفظة البوت بمرجع فريد | فشل: تنفيذ `failed` + ‏`refund_order` — محفظة الموقع تُسترد لحظيًا (هجرة 010)، والتحويل النقدي بيولّد التزام استرداد للمالك (هجرة 008) |
| إشعار webhook + مسح دوري (sweep) | `POST /sheerid/callback` (200 دايمًا، القرار من سؤال خادمي) + `POST /sheerid/sweep` بترويسة الأدمن |
| أي عطل = مسار يدوي بإشعار إدارة | نفس الشيء: حالة `manual_fallback` معلنة للعميل + تنبيه في سجل الأخطاء المركزي |

## الملفات

- `config.ts` — البيئة والثوابت (نفس أسماء متغيرات البوت).
- `client.ts` — عميل خدمة التحقق (ترويسة X-API-Key، مظروف ok/data،
  نقل قابل للحقن للاختبارات).
- `texts.ts` — نصوص العميل الثابتة (علامة بيضاء: لا اسم مورد ولا
  معرّفات ولا أرصدة) + نصوص الإدارة لسجل الأخطاء بس.
- `service.ts` — منطق الدورة والتسوية وضمان التسليم.
- `repo.ts` — تخزين العمليات (ذاكرة للاختبارات / PostgREST للإنتاج)
  + منفذ الطلبات والاسترداد بآليات المتجر.
- `mod.ts` — بناء الخدمة من البيئة + معالج المسارات الأربعة +
  منبّه إيميل Brevo بنفس تهيئة `store_executor/notify.ts`.
- `migration_018_sheerid_jobs.sql` — جدول العمليات (طُبِّقت على الإنتاج 2026-11-18).
- `sheerid.test.ts` — اختبارات على نقل وهمي (`deno test sheerid/`).
- `drill/` — تدريب طبقة القاعدة على Staging (فيه فرع محفظة
  refund_order اللي الذاكرة ما بتغطيهوش).

## التفعيل (ملخص — القائمة الكاملة في تقرير التسليم)

1. تطبيق هجرة 018 على Staging + تشغيل `drill/` + تطبيقها على الإنتاج.
2. ضبط `SHEERID_API_KEY` في بيئة Deno (خطوة مالك من موبايله — مفتاح
   الموقع منفصل عن مفتاح البوت) واختياريًا `SHEERID_WEBHOOK_URL`
   بيشاور على `/sheerid/callback`.
3. إدخال صف الكتالوج (`Google Student (سنة كاملة)`, 280, sub).
4. دمج الفرع (بينشر البطاقة ولوحة الفاتورة وخلفية Deno).
5. ربط `POST /sheerid/sweep` بمجدول خارجي (نمط exec-sweep) +
   تمويل محفظة خدمة التحقق عند المورد قبل أول طلب حقيقي.
